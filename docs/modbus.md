# Modbus RTU 通信

主机代码：`modbus/modbus.c/h`（运行在 86 盒）
从机代码：`modbus/stm32_slave/stm32_modbus_slave.c`（STM32F103C8T6 + 继电器，Keil/Cube 工程文件，不参与主程序编译）

物理层：MAX13487 RS485 收发器，自动收发方向（无需 DE/RE 控制），A/B 双绞线连接主从机。

## 协议栈（纯手写）

不依赖 libmodbus，实现 Modbus RTU 主机最小集：

### 帧格式

```
[ 从机地址 1B ][ 功能码 1B ][ 数据 N B ][ CRC16 低 1B ][ CRC16 高 1B ]
```

### 支持的功能码

| 功能码 | 用途 | 用在 |
|---|---|---|
| 0x03 | 读保持寄存器（一批） | 周期轮询从机状态 |
| 0x06 | 写单个寄存器 | 下发控制命令 |

### CRC16

查表法（MODBUS 多项式 0xA001），两字节小端附帧尾。

### 切帧判据：T3.5 静默时间

9600bps 下字符间隔约 1.15ms，帧间静默 3.5 字符时间 ≈ 3.65ms。主机用 `select()` 串口超时实现：收到首字节后若 3.5 字符时间内无新字节即认为一帧结束——这是应对 RS485 无硬件帧边界（与 TCP 粘包同理）的标准解法。

## 寄存器约定（主从共同遵守）

| 地址 | 含义 | 读写 | 说明 |
|---|---|---|---|
| 0x0000 | 空调开关 | RW | 0 关 / 1 开 |
| 0x0001 | 温度 ×10 | RO | 25.6℃ → 256 |
| 0x0002 | 湿度 ×10 | RO | 56.7% → 567 |
| 0x0003 | 客厅灯 | RW | |
| 0x0004 | 卧室灯 | RW | |
| 0x0005 | 客厅窗帘 | RW | |
| 0x0006 | 卧室窗帘 | RW | |

从机地址、寄存器地址均做成宏，改一处编译期生效。

## 线程模型

```c
modbus_init("/dev/ttyS2", 9600);   /* main.c 调用, 起后台线程 */

/* 后台线程每轮(500ms):
 *   1. 逐条消化期望值队列 → 06 写
 *   2. 03 读全部寄存器 → 更新共享状态(带锁)
 *   3. 连续 3 次无响应 → 标记从机离线, 卡片显示"设备离线"但仍可点
 */
int  modbus_write(int reg, int val);   /* 非阻塞: 只登记期望值, 立即返回 */
int  modbus_get_ac_state(void);        /* UI/上报侧读真实值 */
```

`modbus_write()` 是**登记**不是**发送**——调用方（UI 点击回调 / MQTT 回调）永远不会阻塞在串口上。

## 交互设计：乐观更新

```
用户点卡片 ──► 卡片立即变色(乐观)
              └► modbus_write 登记期望值
                    └► 下轮 06 写 ──► 从机执行
从机回读 ──► UI timer 检测值变化 ──► 以真值刷新卡片
                                  └► 触发 MQTT 状态上报
```

为什么不是"应答成功才变色"：串口往返近百毫秒，UI 等 UI 等它就是卡顿。真值回读天然纠正一切偏差——从机断电重启后，卡片一两秒内自动同步真实状态。

## STM32 从机要点

- USART1（PA9/PA10）+ MAX13487，中断收字节，T3.5 软件定时器切帧（主从同一套切帧思想）
- 地址 0x01，只应答 03/06，其它功能码返回异常码 0x01
- 寄存器写联动 GPIO：继电器低有效，灯/窗帘/空调由从机继电器驱动
- 温湿度寄存器由从机填充（从机也可挂自己的传感器）

## 无硬件联调

开发期用 **USB 转 RS485 模块** 接 PC，PC 端跑脚本模拟从机应答（对收到的 03 帧回数据、06 帧回镜像），即可在没有 STM32 的情况下验证整条链路。板上另有降级逻辑：`modbus_init` 打不开串口返回 -1 进入离线态——卡片可点、显示"设备离线"、不崩，**先烧 UI 后接硬件**的开发顺序因此可行。
